# D7 — server-backed atomic lore backups and per-card restores

Changed: js/lore-store.js and tests/message-chunks.mjs. Original .bak backups retained; a temporary pre-D7 source snapshot was used solely to demonstrate regressions.

Delete and merge read current server cards and write their backup parts/index plus the card change in the same guarded transaction. Deleted-note removal reads fresh cards inside each mutation transaction and retries its backup alongside the card if a concurrent note arrives. Import reads actual existing cards in bounded groups of three, backs up those server copies, and records created IDs from server existence. It returns one backup group across those chunks. Caller/UI card copies no longer determine those backups.

Restore uses one guarded transaction per card: read the current server card and backup index, back up current data (or record that the restore creates a missing card), and restore/delete the card atomically. If restored timestamps precede memoryState.lastUpdateAt, the same transaction marks needsRebuild and the earliest affected src, preserving an earlier existing rebuildFromOrder.

Ordinary backups publish all parts, index and retention pruning in one transaction below an 8 MiB safety threshold. Oversized standalone backups write a preparation lease to the index, write guarded parts, and publish last. Listing scans parts and sweeps unreferenced ones after rechecking the current index transactionally. Active preparations are protected for one hour; abandoned preparations become eligible for cleanup after expiry. This avoids another device's listing deleting an in-progress backup. Existing backup indexes/legacy parts remain readable.

Tests: nine new D7 tests all fail against the pre-D7 source and pass after. Coverage: stale UI delete→restore preserves server-only notes; stale import existence/undo; restore captures current server data and sets rebuild flags; atomic backup publication/failure; indexed/live staged parts survive orphan sweeping; failed second-card restore leaves an undo for the first; merge preserves unseen notes; racing note removal retries its backup; oversized staging failure stays unpublished and is swept after expiry. Focused message-chunks plus production-lore: 68/68 pass. Existing U3 test now expects two reads per initialized atomic backup and index-plus-part reads when listing. Concurrent full-suite snapshot before the final extra test: 437 tests, 391 passed, 46 failures in other active C3/context/cache edits; root was informed.

Reads/writes: normal narrator/extraction per-turn counts and LLM calls unchanged. Manual delete adds the current card read; merge retains its two card reads and adds the backup-index read in the mutation. Restore adds one card read and one index read per card (plus D4 session guard); import reads each affected existing/missing card and one index per three-card group. Remove retains full-history/preflight reads and adds an index read per changed card. Initialized standalone ordinary backup uses two reads: existing session and backup index. Listing now reads the index plus every backup part; orphan cleanup additionally reads session and fresh index per 450-part sweep. Card backups/index writes remain required writes, but restore/import over multiple cards/groups may update the common backup index multiple times. Oversized staging adds a preparation-index write. Optional restore rebuild flags share the card transaction's session write.

Failure behavior: a card mutation transaction writes neither its backup nor card changes when it fails. A later failure in multi-card restore/import/removal leaves earlier committed cards with a discoverable common backup group; the existing UI shows the error, and Backups can undo the completed portion. Oversized failure leaves no visible incomplete backup; staged parts remain protected temporarily and are swept on later listing after expiry. The session tombstone blocks all these guarded writes. No browser/live Firestore verification claimed. B3 partial extraction and B13 reorganize semantics were deliberately left to their owners.
