# D6 — resumable continuity migration

Changed: js/messages.js, tests/message-chunks.mjs. Original backups retained under production-backups/.

Each unfinished legacy chunk migrates in its own transaction, reading its session and chunk, checking historyRevision and nextOrder, and writing only that chunk with continuityVersion: 2. Already marked chunks are skipped. Only after all chunks finish does a final transaction check session history and set continuityVersion, nextNarratorTurn and activeChunkBytes. Existing optional chunk fields remain compatible with older data.

Tests: message-chunks before 41/41, after 43/43. Both new regression tests fail before the fix: 60 chunks exceed the per-transaction single-chunk condition, and the old all-at-once migration cannot interrupt after three completed transactions. The fixed migration bounds writes and resumes without rewriting completed chunks. Latest concurrent full suite: 324 tests, 323 pass, one failure in the unrelated multi-call summarizer source-change regression.

Reads: normal turns after migration unchanged. For N unfinished chunks, migration reads the query's N chunks, then session plus chunk per transaction, plus session at finalization, along with existing startup session reads. This adds N session reads compared with the old single large transaction. The plan's expectation of unchanged total reads cannot hold while rechecking the session inside every per-chunk transaction. Restart skips transaction reads/writes for completed chunks but still loads the chunk query to derive global turns and counters.

Writes: same N chunk writes plus one final session write for an uninterrupted migration; failed transaction attempts commit nothing. On interruption, completed chunk metadata remains, the session marker remains unset, and the current send/edit reports the migration error. The next attempt resumes. There is no user-message deletion or rewrite of narrative content. No new LLM calls. No browser/live Firestore verification claimed.
