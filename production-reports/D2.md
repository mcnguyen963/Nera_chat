# D2 — transactional narrator save guards

Changed: js/messages.js, tests/message-chunks.mjs. Original backups retained under production-backups/.

HistoryConflict is exported from messages.js. Assistant addMessage checks the narrow expected history revision within the save transaction. overwriteMessage checks it within changeMessage, requires the target still be an assistant, and rejects any later non-summary message across chunks. Trailing summaries are allowed. Missing targets report HistoryConflict. Root implements the corresponding narrator expectedSource call sites and unsaved reply UI in D1.

Tests: focused message-chunks baseline 37/37, after 41/41; four new tests (three fail before, read-count invariant already passes before). An existing stale assistant assertion now requires HistoryConflict instead of the old discarded-text wording. Concurrent full suite snapshot: 322 tests, 317 passed; five failures in other actively edited areas, reported to root.

Reads: normal assistant add save still reads just the existing session document in one transaction (0 additional reads). Overwrite discovers chunks with lastOrder greater than the target order; this query costs one read per returned chunk (Firestore minimum query charge applies), and the transaction additionally reads each distinct later chunk. Target chunk is already read. Direct legacy overwrite callers omitting expectedSource additionally read the session before discovery. Root narrator call sites supply expectedSource.

Writes and LLM calls: unchanged; at most two LLM calls per turn remains. A conflict causes no writes. Firestore save transaction failure is atomic; D1 retains completed paid text with local Not saved actions. No browser or live Firestore checks were claimed.
