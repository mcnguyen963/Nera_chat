# D4 — tombstone-first story deletion and guarded writes

Changed: js/sessions.js, js/messages.js, js/lore-store.js, js/ui/sidebar.js, tests/message-chunks.mjs. Original backups retained. Root's errors.js supplies shared StoryDeleted/assertStory; root also handles active-chat tombstones and in-memory cache/unsaved cleanup.

Delete first atomically marks the session deleting with a server timestamp and advances historyRevision. Sessions feeds hide deleting/importing documents. Deleting documents automatically resume through a serialized, deduplicated sweep queue. Persisted IndexedDB chat cache and unsaved reply are cleared before sweeping chunks, legacy messages, lore, backup parts and backup indexes; the session tombstone is deleted last. An interrupted sweep retains a hidden tombstone, and future snapshots/startup or an explicit resume completes it. Repeated sweeps are safe.

All session-touching transactions in the owned modules assert an existing non-deleting session. Blind lore revision increments no longer swallow not-found. Former blind card/backup writes now use guarded transactions. Extraction and narrator save use their already-existing session read. Packed migrations/import writes and copied chunks are guarded. Duplicate destinations now have an unpublished importing session before writing subcollections, and publish only after guarded chunks/lore finish. copyLore guards both source and destination; source deletion cannot create orphan cards. createSession(title,{importing:true}) is available for D5 and accepts only the explicit importing boolean option.

Sidebar deletion disables its button, rejects busy deletion visibly, checks setSession(null)'s refusal, catches failures, and distinguishes a failed tombstone from a paused sweep. Root owns remaining sidebar robustness work. Manual check needed: double-click Delete while a reply runs and confirm a refusal; interrupt deletion after tombstone and verify the hidden story is swept on reconnect.

Regression verification: four D4 tests ran against the original backed-up sources and all failed; they pass with the implementation. Cases cover tombstone blocking reply/extraction/card/backup writes, missing-story orphan prevention, an injected second sweep-batch failure followed by resumed/idempotent completion, and hiding unpublished imports without sweeping them. Focused message-chunks plus production-lore: 53/53 pass. Updated the existing backup-read invariant from one read to three because its guard now reads the session for both part and index writes. Latest concurrent full suite: 365 tests, 359 pass; six failures in other in-progress reasoning/scene changes were reported to root.

Reads/writes: normal narrator add and extraction add no reads or writes. Delete adds one tombstone write, one transaction session read and one resume session read; subtree query/deletes are as before (empty queries have Firestore minimum charges). Generic manual lore mutations add one gate transaction session read and one session read per underlying card transaction. Backups add one session read for every part/index/pruning transaction. Bulk card writes now use bounded groups of six, each reading its session; copies also read their source session. These are user actions, not extra per-turn extraction reads. The extra Firestore rule get() was deliberately skipped per the plan default, so no rule read is charged. Owner-managed UID/sign-up restrictions are outside this change.

Failure paths: if tombstone fails, the original story remains and the sidebar says Try again. Once tombstoned, a failed batch leaves the story hidden and resumable; no writer can commit subcollection creates after seeing the tombstone. Individual guarded card/backup transactions are atomic. Multi-part manual operations can finish earlier guarded transactions before a tombstone/failure blocks the rest; deletion then sweeps all parts. Duplicate/import destinations stay hidden until publication and failed copies are tombstoned/swept. LLM call count is unchanged (at most two per turn). No deployed/browser/live Firestore checks claimed.
