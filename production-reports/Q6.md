# Q6 — pet geometry during streaming

Implemented 2026-10-08. Files changed: `js/ui/pet-view.js`, `tests/pets.mjs`. Original files backed up under `production-backups/Q6/`; no git used.

An IntersectionObserver maintains the visible set for message text and related text obstacles. Message-list element additions/removals update observed targets; text-node streaming changes only invalidate geometry and do not rescan the element list. Removed targets are unobserved. Geometry reads rectangles only from the visible set. Browsers without IntersectionObserver retain viewport filtering. Existing collision protection for controls remains.

The central measurement function enforces a 150 ms minimum interval while the app is busy or the pet is in a turn phase. Per-frame position validation and direct placement/drag calls share this guard. A skipped measurement keeps layout dirty for a later frame. The unused `settings-visibility-changed` listener from Q5 was removed as explicitly assigned with this task; the existing class MutationObserver still suspends pets in Settings.

Tests: two regression harness tests cover IntersectionObserver visibility, repeated streaming scroll frames, direct drag placement, removed target cleanup, and the unsupported-observer fallback. Both fail with the original controller in an isolated temporary tree and pass afterward. Pet suite 16/16. Before full suite during parallel work: 365 tests, 359 pass; after: 367 tests, 366 pass. The sole remaining Reasoning-budget/settings regression belongs to concurrent settings work. JavaScript syntax check passes.

Firestore reads/writes: unchanged, 0 added per turn. LLM calls unchanged, at most 2. No database write path touched or new halfway-save behavior. The tests use a deterministic DOM/clock fixture; an actual browser performance trace on a long streaming story remains part of owner desktop/iPhone acceptance.
