# Roleplay default prompts

These defaults belong to the character continuity pipeline. The application keeps
the narrator contract separate from the selected mode's tool/output instructions.
Do not paste the entire collection into the editable narrator prompt field.

| Prompt | Where it is used |
|---|---|
| [Narrator](continuity-narrator.md) | First system message for Reviewed and Saver turns |
| [Reviewed tools](continuity-tools.md) | Independent second system message in Reviewed mode; API tool schemas remain separate request fields |
| [Saver](continuity-saver.md) | Independent second system message in Saver mode, followed by its generated output schema |
| [State reviewer](continuity-reviewer.md) | System message for Reviewed checks, explicit Saver state repair, and migration-state preparation, followed by the review schema |
| [Prose style](continuity-style.md) | Default editable Continuity prose preferences in Settings; included as stylePreferences in the current-turn data packet |
| [Transcript migration](migration-transcript.md) | Copy to an external LLM with a JSON/JSONL transcript to produce the author note for migration; this prompt is not automatically called or injected each turn |
| [Reviewed author note template](migration-author-note.md) | Fill with verified current story facts, then paste the completed note into the migration field; includes review guidance and when to save/reuse it |

## Migrating an ongoing story

1. Give the transcript migration prompt and your transcript to an LLM, or write
   the state note yourself.
2. Check the note, especially current relationships, unresolved consequences,
   knowledge acquisition, contradictions, and the exact stopping point. Resolve
   consequential uncertain assertions before treating the note as author canon.
3. Open **Settings → This story → Create continuity copy of this story** and paste
   the reviewed note. The app makes one state-review request to prepare records.
4. Check the preview, select Reviewed or Saver, and create the copy. The original
   story is preserved. Use the state table to make further author corrections.

The extraction prompt creates reference prose for human review. The runtime
reviewer converts that reviewed note into the actual application schema. Do not
paste extraction instructions in place of a completed state note.

## Defaults and editing

The five runtime defaults are exported from `js/continuity/prompts.js`.
After editing a Markdown source, run:

```sh
node js/continuity/build-prompts.mjs
node js/continuity/build-prompts.mjs --check
```

Application contracts are not merged into editable prose preferences. New
settings receive the prose default; existing saved custom or blank preferences
remain as saved. **Prompts → Defaults → Save** applies the current prose default
to an existing account along with that panel's other prompt defaults.

The legacy narrator and optional transcript summarizer still use
`narratvie_default_prompt.md` and `summary_default.md`. Those prompts retain their
separate workflows; legacy `<plan>` and `<plan_thread>` instructions are not
injected into continuity turns. Saver uses its structured changes and makes no
separate short-memory or summary request.

The output schemas are generated by the application and remain authoritative.
These prompts improve the behavioral instructions; they do not guarantee model
compliance or replace local validation. Saver has no independent semantic check
on ordinary auto-saved turns. Changing an open consequence or its relationship
can still require review even when the development is justified.
