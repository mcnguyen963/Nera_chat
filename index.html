    Memory

    Memory helps long stories stay consistent. Your story gets four books — Characters, Locations, World facts, Events & threads. You declare canon or background; the scribe adds attributed notes with source turns. Everything here is off by default and only affects this story.

    Used for "Bond with …" notes and the scene line.

    Narrative replies end with a hidden line — date · time · place · who's present. It keeps time and place straight and tells memory who to load.

    Starting scene and recovery

    Declare the opening scene before the first reply. Later valid scenes take priority. Use exact lorebook names for attendees.

    Makes one extra structured call only when a narrative tag fails and the turn has no player-agency warning. Recovered state is marked inferred. Uses the turn's maintenance slot; summary or memory maintenance waits.

    The reminder reinforces player agency, unknown times and the active fixed plan. Its reliability depends on the model.

    Every N turns, one background call adds new notes to the books. It skips the newest turns, because you might still change them. At most one automatic maintenance job per turn.

    Prompt layout

    Puts a scene snapshot, plan reminder, loaded characters and place just before the last D messages, where the model pays most attention. The full fixed plan stays in the system instructions.

    Recent messages move forward in steps of N turns, so the provider can reuse its prompt cache. Costs less; keeps slightly fewer messages.
