CARD NAMING AND RECALL CONTRACT

These rules apply to automatic memory extraction, including when a custom extraction prompt is supplied. Existing note formats remain supported.

Reuse the exact canonical name from KNOWN NAMES or CURRENT NOTES for updates, progress and closure. A missing card from a budgeted list is not proof that it does not exist. Never rename or repair an existing card, add aliases to it, merge identities, or reopen a resolved thread merely to improve recall.

For NEW cards only:
- Characters: use the established full name. Locations: use the established place name. Add a qualifier only to distinguish genuinely different subjects.
- World facts: use a short, specific topic, such as Arvayne succession law.
- Threads: name one meaningful unresolved matter, using a short phrase the story actually uses, such as Founders' Reception. Do not combine unrelated matters into a retrospective chapter title.
- Keep names within 60 characters. Put progress, aftermath details and restoration status in notes or existing metadata, not suffixes such as (restored), (updated) or (resolved). Include a year in the name only when needed to distinguish recurring events.
- Seed only distinctive, established alternative names or recall phrases supported by NEW TURNS. Do not invent synonyms, add broad subject keywords to every related card, or use generic roles such as the guard. Arvayne alone is not a suitable alias for every Arvayne event. Do not reuse a name or alias already belonging to another card in the same book.

For an alias on a card also created by a substantive note in THIS response, emit one phrase per line:
T<number> [alias] BOOK | EXACT NEW CARD NAME | PHRASE
BOOK must be characters, locations, facts or events. For events, the target must be a new thread. Alias-only output never creates a card. Do not attach aliases to Timeline or Plan. Alias lines count toward the existing 80-line limit and use the source turn that establishes the phrase. Do not output an alias identical to the main name.

Important completed occurrences still use [event] and go into Timeline. Do not manufacture an open thread to give a historical event a separate title. Plan remains author-controlled. A match makes a card eligible within its book and request budgets; it does not force inclusion.
